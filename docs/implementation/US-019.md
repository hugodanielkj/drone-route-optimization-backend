# US-019 — Listar missões do usuário autenticado

## O que foi pedido

`GET /missoes` retorna todas as missões (ativas e desativadas) pertencentes
ao usuário autenticado; usuário sem missões recebe lista vazia; missões de
outros usuários nunca aparecem.

## Decisões de contrato tomadas com o usuário

- **Listagem usa só `droneId`/`mapaId` (ids), não objetos aninhados de Drone
  e Mapa** — mesma granularidade já usada em create/detalhe
  (`missao.controller.ts`), sem custo extra de `include` no Prisma.
- **Listagem omite `pernas`** — resumo leve (`id, droneId, mapaId, status,
  consumoEnergeticoTotal, createdAt, updatedAt`). Os critérios de aceite de
  US-019 não mencionam `pernas`/`consumoEnergeticoTotal` como obrigatórios,
  diferente de US-020 (detalhe), que exige `pernas` completo explicitamente
  — `pernas` pode ser um array grande em mapas de até 1000 pontos (RN16),
  então evitar carregá-lo na listagem é uma escolha deliberada de payload,
  não só de leitura de requisito.

## Passo a passo do que foi implementado

- `src/modules/missao/missao.service.ts` — `listar(usuarioId)`:
  `prisma.missao.findMany({ where: { drone: { userId: usuarioId } } })`.
  `Missao` não tem `userId` próprio — o filtro usa a relação com `Drone`
  (RN11 garante, desde a criação em `calcular`, que `drone.userId ===
  mapa.userId` para toda Missão persistida, então filtrar por qualquer um
  dos dois é equivalente).
- `src/modules/missao/missao.controller.ts` — nova função
  `formatarMissaoResumo` (sem `pernas`) e handler `listar`, respondendo
  `200` com `missoes.map(formatarMissaoResumo)`.
- `src/modules/missao/missao.routes.ts` — `GET /` registrado.

## Alternativas de implementação consideradas

- **Filtrar por `mapa: { userId }` em vez de `drone: { userId }`** —
  equivalente (RN11 garante que são o mesmo usuário); escolhido `drone` só
  por ser o primeiro a aparecer no schema, sem diferença de comportamento.
- **Reaproveitar `formatarMissao` (com `pernas`) também na listagem** —
  descartada pela decisão de contrato acima (payload mais leve).

## Como foi testado

Plano de testes: `docs/tests/US-019-plano.md`. Cobertos em
`missao.controller.spec.ts` (`GET /missoes`): listagem com missões
ativa+desativada e sem `pernas` no corpo, lista vazia, isolamento por
usuário, `401` sem token.
