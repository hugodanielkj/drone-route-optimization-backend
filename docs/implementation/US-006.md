# US-006 — Consultar drone por id

## O que foi pedido

Usuário autenticado consulta um drone específico pelo id, desde que
pertença a ele; id inexistente ou de outro usuário retorna não encontrado,
sem revelar que o recurso existe para outro dono (RF-002.4, RN11).

## Passo a passo do que foi implementado

- `src/modules/drone/drone.service.ts` — `droneService.buscarPorId(usuarioId,
  droneId)`: busca por `id` via `prisma.drone.findUnique` e, em seguida,
  compara `drone.userId` com o `usuarioId` recebido. Se o drone não existir
  **ou** pertencer a outro usuário, lança `NotFoundError` — a mesma resposta
  (`404`) para os dois casos, para não revelar a existência do recurso a
  quem não é dono.
- `src/modules/drone/drone.controller.ts` — `buscarPorId`: chama o service
  com `req.usuarioId` e `req.params.id`, responde `200` com o drone.
- `src/modules/drone/drone.routes.ts` — `GET /:id` registrado.

## Alternativas de implementação consideradas

- **Buscar com `where: { id, userId }` diretamente no Prisma (retornando
  `null` sem distinguir "não existe" de "é de outro usuário")** — equivalente
  em resultado à abordagem escolhida (`findUnique` por id + comparação
  manual), mas a comparação manual deixa explícito no código, para quem ler,
  que a checagem de posse é intencional (RN11) e não um efeito colateral do
  filtro — decisão de legibilidade, sem diferença de comportamento ou
  desempenho relevante neste volume de dados.
- Esta é a checagem de ownership por id que **US-007 e US-008 reaproveitam
  diretamente** (edição e exclusão chamam `buscarPorId` antes de agir),
  evitando duplicar a lógica de "existe e pertence ao usuário" em cada
  operação.

## Como foi testado

Plano de testes: `docs/tests/US-006-plano.md` (5 casos). Todos cobertos em:

- `src/modules/drone/drone.controller.spec.ts` (e2e): caso feliz, id
  formato válido mas inexistente, id qualquer inexistente, drone de outro
  usuário (ambos retornando `404`, sem distinção no corpo) e ausência de
  token.
- `src/modules/drone/drone.service.spec.ts` (unitário): confirma o retorno
  do drone quando pertence ao usuário e `NotFoundError` nos dois cenários de
  negação (inexistente / outro dono).

Suíte rodada com `pnpm test`: 7 suítes, 67 testes, todos passando (nenhuma
regressão em Sprint 01 + US-004/US-005).
