# US-011 — Consultar mapa por id

## O que foi pedido

Usuário autenticado consulta um mapa específico seu, pelo id, obtendo o ponto
de carregamento e todos os pontos de irrigação; id inexistente ou de mapa de
outro usuário retorna não encontrado (nunca `403` — não revela existência do
recurso a quem não é dono).

## Passo a passo do que foi implementado

- `src/modules/mapa/mapa.service.ts` — `mapaService.buscarPorId(usuarioId,
  mapaId)`: réplica exata do padrão de `droneService.buscarPorId` (US-006):
  `prisma.mapa.findUnique` sem filtrar por `userId` na query, seguido de
  `if (!mapa || mapa.userId !== usuarioId) throw new NotFoundError('Mapa não
  encontrado')`. `include: { pontosIrrigacao: true }` para trazer todos os
  pontos exigidos pela história.
- `src/modules/mapa/mapa.controller.ts` — `buscarPorId`: chama o service com
  `req.usuarioId` e `req.params.id`, formata via `formatarMapa`, responde
  `200`.
- `src/modules/mapa/mapa.routes.ts` — `GET /:id` registrado, fechando o escopo
  de leitura/criação do módulo `mapa` para esta sprint.

## Alternativas de implementação consideradas

Nenhuma alternativa relevante — história replica diretamente o padrão de
ownership já validado em US-006 (Drone), sem decisão nova além das já
registradas em US-009 (formato de resposta, ADR-003).

## Como foi testado

Plano de testes: `docs/tests/US-011-plano.md` (5 casos). Todos cobertos em
`src/modules/mapa/mapa.controller.spec.ts` (e2e): consulta de mapa próprio com
pontos de irrigação completos, id com formato de UUID válido mas inexistente,
id inexistente, mapa de outro usuário (`404`, nunca `403`), ausência de token.
Cobertura unitária em `src/modules/mapa/mapa.service.spec.ts`
(`mapaService.buscarPorId`): retorno correto, `NotFoundError` para inexistente
e para mapa de outro usuário.

Suíte rodada com `pnpm test`: 9 suítes, 135 testes, todos passando. `pnpm
typecheck` sem erros. Sem regressão em Sprint 01 + Sprint 02 + US-009 + US-010
— **Sprint 03 completa** (US-009 a US-011).
