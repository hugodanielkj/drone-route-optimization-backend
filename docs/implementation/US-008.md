# US-008 — Excluir drone

## O que foi pedido

Usuário autenticado exclui um drone próprio; a exclusão é recusada se
existir qualquer Missão (ativa ou desativada) associada ao drone (RN15);
drone de outro usuário retorna não encontrado.

## Passo a passo do que foi implementado

- `src/modules/drone/drone.service.ts` — `droneService.excluir(usuarioId,
  droneId)`:
  1. Reaproveita `droneService.buscarPorId` (US-006) para a checagem de
     ownership.
  2. `prisma.missao.count({ where: { droneId } })` — conta Missões
     associadas **sem filtrar por status**, já que RN15 bloqueia a
     exclusão tanto para Missão ativa quanto desativada. Se houver
     qualquer uma, lança `ConflictError`.
  3. `prisma.drone.delete`, executado apenas se a contagem for zero.
- `src/modules/drone/drone.controller.ts` — `excluir`: chama o service e
  responde `204` sem corpo em caso de sucesso.
- `src/modules/drone/drone.routes.ts` — `DELETE /:id` registrado, fechando
  o CRUD completo do módulo `drone`.

## Alternativas de implementação consideradas

- **Filtrar a contagem de Missões por status `ATIVA`** — descartada: RN15 é
  explícita ("ativa ou desativada"), diferente de RN13 (que só desativa
  Missões `ATIVA`). Usar `count` sem filtro de status evita reproduzir por
  engano a lógica de RN13 aqui.
- **Responder `200` com corpo (ex: `{ excluido: true }`) em vez de `204`
  sem corpo** — descartada por seguir a convenção REST padrão: `DELETE`
  bem-sucedido sem conteúdo a retornar usa `204 No Content`.
- **`409` como status de erro para RN15** — escolhido por ser a semântica
  HTTP mais próxima de "o estado atual do recurso impede a operação"
  (conflito), reaproveitando a classe `ConflictError` já existente em
  `common/errors/app-error.ts` (mesma usada por "nome de usuário já em
  uso" em US-001).

## Como foi testado

Plano de testes: `docs/tests/US-008-plano.md` (8 casos, incluindo 3
dedicados a RN15). Todos cobertos em:

- `src/modules/drone/drone.controller.spec.ts` (e2e): exclusão bem-sucedida
  sem Missão associada, isolamento entre drones do mesmo usuário, drone
  inexistente, drone de outro usuário (não excluído), ausência de token, e
  os 3 casos de RN15 (bloqueio com Missão `ATIVA`, bloqueio com Missão
  `DESATIVADA`, e exclusão permitida de um drone sem Missão mesmo quando
  outro drone do mesmo usuário tem Missão associada) — fixtures de `Missao`
  inseridas diretamente via `prisma.missao.create`.
- `src/modules/drone/drone.service.spec.ts` (unitário): exclusão bem
  sucedida, `NotFoundError` para drone de outro usuário, `ConflictError`
  (com verificação de que o drone permanece no banco) quando há Missão
  associada.

Suíte rodada com `pnpm test`: 7 suítes, 100 testes, todos passando (nenhuma
regressão em Sprint 01 + US-004 a US-007).
