# US-010 — Listar mapas do usuário autenticado

## O que foi pedido

Usuário autenticado lista todos os seus mapas cadastrados; mapas de outros
usuários não aparecem no resultado; lista vazia quando não há mapas.

## Passo a passo do que foi implementado

- `src/modules/mapa/mapa.service.ts` — `mapaService.listar(usuarioId)`:
  `prisma.mapa.findMany({ where: { userId: usuarioId }, include: {
  pontosIrrigacao: true } })`.
- `src/modules/mapa/mapa.controller.ts` — `listar`: chama o service e mapeia
  cada item do array pelo mesmo `formatarMapa` usado em `cadastrar` (US-009),
  respondendo `200`.
- `src/modules/mapa/mapa.routes.ts` — `GET /` registrado.

## Alternativas de implementação consideradas

- **Omitir `pontosIrrigacao` da listagem, já que US-010 não exige
  explicitamente os pontos no corpo da resposta** — descartada: manter uma
  única forma de representação do Mapa (a mesma usada em `cadastrar` e
  `buscarPorId`, via `formatarMapa`) evita dois shapes diferentes para o mesmo
  recurso, sem custo relevante (mesma query de `include` já usada nas outras
  operações).

## Como foi testado

Plano de testes: `docs/tests/US-010-plano.md` (5 casos). Todos cobertos em
`src/modules/mapa/mapa.controller.spec.ts` (e2e): listagem de todos os mapas
do usuário, lista vazia, muitos mapas do mesmo usuário, isolamento entre
usuários, ausência de token. Cobertura unitária correspondente em
`src/modules/mapa/mapa.service.spec.ts` (`mapaService.listar`).

Suíte rodada com `pnpm test`: 9 suítes, 135 testes, todos passando (nenhuma
regressão em Sprint 01 + Sprint 02 + US-009).
