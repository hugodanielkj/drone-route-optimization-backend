# US-017 — Reaproveitar missão ativa existente

## O que foi pedido

Uma segunda solicitação de cálculo (`POST /missoes`) para um par (drone,
mapa) que já tem Missão ativa retorna o resultado já persistido, sem
recalcular e sem alterar nenhum dado.

## Decisões de contrato tomadas com o usuário

- **`200`, não `201`**, quando `POST /missoes` reaproveita uma Missão ativa
  existente — `201` fica reservado exclusivamente para a criação de fato
  (US-016). Mesma decisão vale para o recálculo/reativação (US-018).
- **`missaoService.calcular` muda de assinatura**: passou a retornar
  `{ missao, criada: boolean }` em vez de só `Missao`, para o controller
  decidir `201` vs `200` sem precisar inferir isso de heurísticas frágeis
  (como comparar `createdAt`/`updatedAt`, que seriam iguais tanto para uma
  Missão recém-criada quanto para uma reaproveitada sem nenhuma escrita).

## Passo a passo do que foi implementado

- `src/modules/missao/missao.service.ts` — `calcular` agora busca a Missão
  existente e ramifica por `status`: se `ATIVA`, retorna
  `{ missao: missaoExistente, criada: false }` diretamente, **sem nenhuma
  chamada de escrita ao Prisma** (garante RN12: nenhum dado alterado). Os
  ramos "não existe" (US-016, cria) e "desativada" (US-018, recalcula) foram
  mantidos/adicionados na mesma função — ver `docs/implementation/US-018.md`
  para o ramo de recálculo.
- `src/modules/missao/missao.controller.ts` — `calcular` usa `criada` para
  escolher `res.status(criada ? 201 : 200)`.

## Alternativas de implementação consideradas

- **Endpoint separado para "obter Missão existente"** — descartada: RF-004
  já define que `POST /missoes` é o único ponto de entrada, ramificando
  internamente por estado (criar/reaproveitar/recalcular); não há requisito
  para um endpoint de consulta direta por par (isso é US-020, por id).
- **Inferir `criada` a partir de `createdAt === updatedAt`** — descartada:
  ambíguo (uma Missão recém-criada e uma reaproveitada sem nenhuma escrita
  têm exatamente essa mesma característica); o retorno explícito
  `{ missao, criada }` remove a ambiguidade.
