# US-003 — Proteção de rotas autenticadas

**Como** usuário do sistema,
**quero** que meus drones, mapas e missões só sejam acessíveis mediante
autenticação,
**para** garantir que outros usuários não vejam nem alterem meus dados.

## Requisito de origem

RF-001.5 (RN11)

## Critérios de aceite

- **Given** uma requisição sem token de acesso, **when** ela é feita a qualquer
  rota de Drone, Mapa ou Missão, **then** o sistema recusa com erro de não
  autenticado, sem executar a lógica de negócio.
- **Given** uma requisição com um token inválido ou expirado, **when** ela é feita
  a qualquer rota de Drone, Mapa ou Missão, **then** o sistema recusa com erro de
  não autenticado.
- **Given** uma requisição com token válido, **when** ela é feita a uma rota
  protegida, **then** o sistema identifica o usuário autenticado e permite que a
  lógica de negócio prossiga, restringindo o acesso apenas aos recursos desse
  usuário.
- **Given** um usuário autenticado tentando acessar um Drone, Mapa ou Missão que
  pertence a outro usuário, **when** a requisição é feita, **then** o sistema
  recusa o acesso (não encontrado ou não autorizado).

## Fora de escopo

- Cadastro (US-001) e login (US-002), que continuam públicos.
- Controle de papéis/permissões (roles) — fora de escopo do projeto (apenas
  ownership simples).
