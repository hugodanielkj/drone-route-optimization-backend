# US-002 — Login de usuário

**Como** usuário cadastrado,
**quero** fazer login com meu nome e senha,
**para** obter um token de acesso e usar as demais funcionalidades do sistema.

## Requisito de origem

RF-001.4

## Critérios de aceite

- **Given** um usuário cadastrado e a senha correta, **when** ele solicita login,
  **then** o sistema retorna um token de acesso válido.
- **Given** um nome não cadastrado, **when** o login é solicitado, **then** o
  sistema rejeita a requisição sem indicar especificamente se o problema foi o
  nome ou a senha (evita enumeração de usuários).
- **Given** um nome cadastrado e uma senha incorreta, **when** o login é
  solicitado, **then** o sistema rejeita a requisição com a mesma resposta genérica
  do caso anterior.

## Fora de escopo

- Cadastro (US-001).
- Emissão de refresh token, expiração configurável, ou múltiplos dispositivos —
  detalhes do mecanismo de token são decisão técnica via ADR na implementação.
- Logout com invalidação server-side — decisão confirmada de não existir nesta
  fase (token stateless, descarte é responsabilidade do cliente).
